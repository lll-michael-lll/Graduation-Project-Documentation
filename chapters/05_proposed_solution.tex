\section{Solution Overview}

The proposed solution is \textbf{zGate}, a comprehensive Zero-Trust Database Access Platform that fundamentally changes how organizations manage database security and access control. Rather than relying on shared credentials and static permissions, zGate introduces a dynamic, policy-driven approach where temporary credentials are created for each user session, eliminating the risks associated with credential sprawl and unauthorized access.

\subsection{The Core Problem}

Traditional database access models suffer from several critical security and operational challenges:

\begin{enumerate}
    \item \textbf{Shared Credentials:} Multiple users share common database accounts, making it impossible to audit who performed which actions
    \item \textbf{Static Permissions:} Once granted, permissions remain indefinitely, increasing the attack surface
    \item \textbf{Credential Sprawl:} Database passwords stored in configuration files, wikis, and password managers
    \item \textbf{Lack of Visibility:} No centralized view of who has access to which databases
    \item \textbf{Manual Overhead:} Granting and revoking access requires manual database administration
    \item \textbf{Compliance Gaps:} Difficult to prove least-privilege access and maintain audit trails
\end{enumerate}

\subsection{zGate Server (Backend)}

The server is the heart of the platform, handling all security, policy enforcement, and proxy operations.

\subsubsection{Backend Layers}
\begin{figure}[H]
    \centering
    \includegraphics[width=\textwidth]{images/backend.png}

The API Layer routes all requests into the Authentication and Identity module (OIDC token validation via Keycloak, JWT HS256 with device fingerprint binding, TOTP 2FA, built-in PKI for mTLS certificate lifecycle, and ALTCHA SHA-256 proof-of-work). The Policy Engine resolves four-tier RBAC permissions and applies safety templates and six compliance frameworks. The six-phase Dispatcher manages connection routing, and every query traverses an eight-stage Interceptor Pipeline: RateLimit, OTel Telemetry, NDJSON Logging, Anomaly detection, SafeQuery AST analysis (gRPC to zGate-Tsql-Parser), RowMask, ColMask, and AI Masking (gRPC to zGate-AI).}
    \label{fig:zgate-backend-architecture}
\end{figure}
\subsubsection{Key Features}

\textbf{1. OIDC + JWT Authentication}
\begin{itemize}
    \item OIDC Device Authorization Grant (CLI) and PKCE browser flow (WebUI) via Keycloak — no static passwords stored or transmitted
    \item Access tokens (HS256, 5-minute default TTL, configurable via \texttt{ZGATE\_ACCESS\_TOKEN\_DURATION}) for API requests
    \item Refresh tokens (1-hour default TTL, configurable via \texttt{ZGATE\_REFRESH\_TOKEN\_DURATION}) for session persistence
    \item Per-token revocation via JTI (JWT ID); per-session revocation via refresh token family ID
    \item Device fingerprint binding (SHA-256 of IP + User-Agent) embedded in every JWT to reject stolen-token replay
    \item Mandatory TOTP two-factor authentication for all admin accounts
\end{itemize}

\textbf{2. Real-Time Policy Enforcement}
\begin{itemize}
    \item Permissions evaluated from current configuration on every request
    \item Role-based access control (RBAC) with support for multiple roles per user
    \item Custom permissions at user level for exceptions
    \item Immediate effect when permissions are changed (no cache invalidation needed)
\end{itemize}

\textbf{3. Dynamic Proxy Management}
\begin{itemize}
    \item On-demand creation of proxy sessions
    \item Automatic port allocation from ephemeral range
    \item Temporary database user creation with appropriate grants
    \item Automatic cleanup on disconnect or crash recovery
\end{itemize}

\textbf{4. Multi-Protocol Wire-Level Proxy}
\begin{itemize}
    \item Three wire-protocol listeners: MySQL (port 9000), PostgreSQL (port 9001), Microsoft SQL Server/TDS (port 9002)
    \item Pluggable \texttt{DatabaseHandler} interface — each protocol implements \texttt{PeekRouting}, \texttt{Handshake}, \texttt{ReadCommand}, \texttt{ForwardResult}
    \item Six-phase \texttt{Dispatcher}: PeekRouting → StartSession → Bind → Backend Dial → Handshake → Command Loop
    \item Database-specific ephemeral credential injection at the wire-protocol handshake layer
\end{itemize}

\textbf{5. Comprehensive Logging}
\begin{itemize}
    \item Structured logging with key-value pairs
    \item Every security event logged with user context
    \item Support for JSON output for log aggregation
    \item Configurable log levels (DEBUG, INFO, WARN, ERROR)
\end{itemize}

\subsection{zGate CLI (Client)}

\subsubsection{CLI Workflow}
\begin{figure}[H]
    \centering
    \includegraphics[width=\textwidth]{images/CLI-workflow.png}
    \caption{zGate-CLI five-phase workflow sequence. Phase~1: OIDC Device Authorization Grant (RFC~8628) --- the CLI obtains a device code from Keycloak, presents a verification URI to the user, polls for approval, then exchanges the ID token for zGate JWT tokens (5-minute access, 1-hour refresh) stored in the OS keyring. Phase~2: mTLS certificate lifecycle --- ECDSA key pair generated locally, CSR submitted to the built-in PKI, signed certificate returned. Phase~3: database connection --- RBAC check, ephemeral credential creation, loopback tunnel established for transparent database client use. Phase~4: transparent token refresh one minute before expiry. Phase~5: secure logout with server-side JTI and family-ID revocation.}

\end{figure}

\section{Security Architecture}

Security is woven into every layer of the zGate platform through multiple defense mechanisms.

\subsection{Security Layers}
\begin{figure}[H]
    \centering
    \includegraphics[width=\textwidth]{images/security-layers.png}
    \caption{zGate seven-layer defence-in-depth security model. Layer~1: TLS~1.3 on all connections with mTLS strict mode for CLI and a 60-second proxy ticket TTL. Layer~2: identity and authentication via OIDC Device Flow / PKCE (no passwords transmitted to clients), ALTCHA SHA-256 proof-of-work on all login endpoints, mandatory TOTP 2FA for admin accounts, and SHA-256 device fingerprinting. Layer~3: token security with JWT HS256, 5-minute access and 1-hour refresh TTLs, per-token JTI revocation, per-session family-ID revocation, and progressive lockout after five failures. Layer~4: four-tier RBAC (super, db\_admin, policy\_admin, auditor) with fresh per-request evaluation. Layer~5: eight-stage interceptor pipeline including a warn flow requiring admin approval within 5~minutes. Layer~6: credential isolation via ephemeral database users deleted within 30~seconds, bcrypt work factor~12, and HashiCorp Vault AppRole for secrets. Layer~7: full observability through per-query NDJSON audit logs, OTLP telemetry exported to the OTel Collector, and ML anomaly risk scores surfaced in the audit dashboard.}
    \label{fig:security-layers}
\end{figure}
