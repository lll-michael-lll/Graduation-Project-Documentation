\begin{sectionintro}{18}{Roadmap for the Future}{
  \begin{itemize}[leftmargin=1.5em]
    \item Native identity provider connectors
    \item Enterprise SIEM \& alerting integrations
    \item Advanced dynamic query rewriting
    \item Performance tuning to sub-1ms latencies
    \item Hardware security module \& secure enclaves
    \item Chaos \& fuzz testing strategies
  \end{itemize}
}
With the core zGate features fully implemented and validated, this chapter outlines the roadmap for what is next for the platform. We focus on transitioning from a single-instance gateway to a globally scalable, enterprise-grade Zero-Trust database security mesh. We detail plans for native directory integrations (SCIM), automated alerting webhooks, dynamic SQL query rewriting, and cell-level filtering, establishing future performance targets of sub-1ms latency and 10,000+ concurrent connections, alongside hardware-assisted security hardening and advanced chaos validation.
\end{sectionintro}

The core implementation of zGate has validated the feasibility of transparent, identity-aware database wire proxying. Building upon the functional, security-hardened system now in place, the future roadmap focuses on three primary areas: scaling the proxy architecture to multi-region deployments, enhancing security boundaries through hardware-assisted isolation, and expanding the AST and AI policy capabilities.

\section{Remaining Features}
% ============================================================

The following features are scheduled for future development phases, expanding the capabilities of the zGate platform.

\subsection{External Identity Provider Integration (Milestone 4)}

While Keycloak integration provides standard OIDC and OAuth2 capability, future iterations will support federated identity management directly inside the gateway core to optimize connection routing:
\begin{itemize}
    \item \textbf{Native Directory Connectors:} Build native connectors for Active Directory (LDAP/AD) and cloud directories (Azure AD/Entra ID, Okta, Google Workspace) to query user groups and status dynamically without HTTP redirect hops.
    \item \textbf{SCIM Directory Syncing:} Implement the System for Cross-domain Identity Management (SCIM) protocol to synchronize user lifecycle events, permissions, and group adjustments in real-time.
    \item \textbf{Graphical Claims Mapper:} Implement a visual interface inside the WebUI admin dashboard to drag-and-drop identity claims (IdP groups, organization units) to internal zGate roles.
    \item \textbf{Just-in-Time Provisioning Extensions:} Support automatic mapping of user attributes and role assignment on first database connection query.
\end{itemize}

\subsection{Enhanced Observability Features (Milestone 5)}

Translate the local metrics and Jaeger tracing integrations into an enterprise-ready security operations center compliance platform:
\begin{itemize}
    \item \textbf{SIEM Connectors:} Implement native exporter hooks for Security Information and Event Management (SIEM) systems, including Splunk, Datadog, and the ELK stack.
    \item \textbf{Alert Dispatching Webhooks:} Implement native notification integrations inside the gateway server, allowing immediate alert pushes to Slack, Microsoft Teams, and PagerDuty when anomalies are detected.
    \item \textbf{Cryptographic Log Signatures:} Bind query and session log files with SHA-256 HMAC chained hashes to guarantee that audit files are tamper-evident and audit-compliant.
\end{itemize}

\subsection{Advanced Policy Engine Enhancements}

Extend the AST interceptor pipeline to provide finer control over query execution limits and database results:
\begin{itemize}
    \item \textbf{Dynamic Query Rewriting:} Implement dynamic SQL rewriting. The AST pipeline will automatically append database filters to incoming queries (such as adding `WHERE tenant\_id = 'X'`) to enforce multi-tenancy rules at the proxy layer.
    \item \textbf{Cell-Level Filtering:} Extend data masking to support cell-level filtering based on user role security classifications, selectively redacting cells rather than entire columns.
    \item \textbf{Query Complexity Limits:} Extract query joins and statement weights from the AST sidecar, blocking queries that exceed maximum estimated database costs or complexity limits.
    \item \textbf{Auto-Classification Workers:} Implement continuous background LLM workers that scan target database tables to identify and tag PII fields automatically.
\end{itemize}

\section{Architecture Improvements}

Based on lessons learned during system validation, the following architectural enhancements are planned to support enterprise-scale deployments.

\subsection{Scalability Enhancements}

\begin{itemize}
    \item \textbf{Active-Active Clustering:} Implement a distributed consensus protocol (Raft) to synchronize active connection counters and token states across load-balanced zGate proxy nodes.
    \item \textbf{Distributed Caching:} Introduce a centralized Redis caching layer for policy decisions and session metadata to minimize database lookups.
    \item \textbf{Proxy-Side Multiplexing:} Develop dynamic proxy-side connection pooling to handle larger client connection pools over fewer target database connections.
\end{itemize}

\subsection{Security Hardening}

\begin{itemize}
    \item \textbf{HSM Integration:} Support Hardware Security Modules (HSMs) for securing root CA private keys and signing client certificates.
    \item \textbf{Secure Enclave Execution:} Run core proxy routines inside Secure Enclaves (Intel SGX, AMD SEV) to prevent host OS administrators from inspecting database streams or memory states.
    \item \textbf{Zero-Knowledge Tickets:} Implement zero-knowledge proof ticket validations to authenticate clients without exposing session state details.
\end{itemize}

\subsection{Deployment Improvements}

\begin{itemize}
    \item \textbf{Kubernetes Operator:} Develop a native zGate Kubernetes Operator to automate deployment scaling, config synchronization, and database sidecar injections.
    \item \textbf{Service Mesh Sidecar:} Compile the zGate proxy into a lightweight sidecar binary suitable for deployment in service meshes (such as Istio) for internal pod-to-database communications.
\end{itemize}

\subsection{Optimization Strategies}

To achieve these future performance targets, the following optimization strategies will be employed:
\begin{enumerate}
    \item \textbf{Zero-Copy Parsing:} Optimize protocol parsing hot paths using zero-copy techniques, eliminating memory allocations during wire peeking.
    \item \textbf{Goroutine Worker Pools:} Implement fixed-size goroutine worker pools to prevent CPU thread thrashing under extreme client connection floods.
    \item \textbf{Dynamic Buffer Reuse:} Utilize Go's `sync.Pool` to recycle byte buffers, reducing garbage collection overhead.
\end{enumerate}

\section{Testing \& Validation Plan}

A comprehensive testing strategy will ensure system reliability and security for future version iterations.

\subsection{Automated Testing Framework}

\begin{itemize}
    \item \textbf{Unit Tests:} Achieve a minimum of 90\% code coverage for the proxy server and C\# parsing logic.
    \item \textbf{Integration Tests:} Build automated pipelines that deploy full Compose stacks containing MySQL, PostgreSQL, and MSSQL databases to test AST features on every code push.
\end{itemize}

\subsection{Performance Validation}

\begin{itemize}
    \item \textbf{High-Volume Load Testing:} Utilize `pgbench` and custom benchmark scripts to validate concurrent connections up to 10,000 threads.
    \item \textbf{Distributed Chaos Engineering:} Implement Chaos Mesh to validate proxy fail-open resiliency during sidecar failures or authentication server latencies.
\end{itemize}

\subsection{Security Validation}

\begin{itemize}
    \item \textbf{Protocol Fuzz Testing:} Implement fuzzing tools to test the peeking and connection dispatching handlers against malformed packets.
    \item \textbf{Penetration Testing:} Enlist external security audits to identify bypass vectors, memory leaks, and policy circumventions.
\end{itemize}

\subsection{User Acceptance Testing}

\begin{itemize}
    \item \textbf{Sandbox Environments:} Provide cloud-hosted sandbox environments for administrators to evaluate policy engine updates before deployment.
    \item \textbf{Interactive Documentation:} Deploy interactive swagger and API reference guides.
\end{itemize}
